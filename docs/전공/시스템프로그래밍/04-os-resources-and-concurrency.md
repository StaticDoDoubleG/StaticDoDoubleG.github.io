## 시스템 프로그래밍의 대상

시스템 프로그래밍에선 애플리케이션이 운영체제가 관리하는 자원을 사용하는 방법을 다룬다. <br>
프로그램이 CPU, 메모리, 파일, 장치를 직접 소유하는 것이 아니라 운영체제에 서비스를 요청하고, 운영체제는 권한과 상태를 확인한 뒤 자원을 제공한다.<br>
이 요청 인터페이스가 **시스템 콜**이다.

## 통신, 동시성, 비동기 연산

- 통신: 한 프로세스나 시스템이 다른 대상에게 정보를 전달한다.
- 동시성: 여러 작업이 같은 시간 범위에 진행되거나 CPU·데이터·입출력 장치를 공유한다.
- 비동기 연산: 사건이 발생하는 시점과 순서를 프로그램이 미리 확정할 수 없다.

동시성은 반드시 여러 작업이 물리적으로 같은 순간 실행된다는 뜻이 아니다. 한 CPU에서도 실행을 빠르게 교대하면 여러 작업이 동시에 실행되는 것처럼 보인다. 반대로 여러 CPU가 있어도 공유 데이터에 대한 조정이 없으면 결과가 올바르지 않을 수 있다.

## CPU와 입출력 속도 차이

프로세서는 빠르게 명령을 수행하지만 디스크나 네트워크 입출력은 상대적으로 오래 걸린다. (OS에서 이 부분에 대해 좀 더 자세하게 배울 것이다.)<br>
한 프로그램이 입출력을 기다리는 동안 CPU는 놀게되고, 이걸 활용하지 않으면 시스템 전체 처리량이 낮아진다.<br> 
운영체제는 준비된 다른 프로세스를 실행해 이 대기 시간을 활용한다. 추후 스케줄링과 관련하여 더 구체적인 얘기를 할 수 있는 영역이다. 어쨌든 여기선 개념만 다룬다.

## Multiprogramming

Multiprogramming에서는 둘 이상의 프로세스가 실행 준비 상태에 있을 수 있다. 운영체제는 준비 큐에서 하나를 선택해 CPU를 할당하고, 해당 프로세스가 읽기나 쓰기를 요청해 대기하면 다른 프로세스에 실행 기회를 준다. 여기서 **요청**이 **시스템 콜**이며, 이 요청이 들어오면 CPU는 user mode에서 kernel mode로 전환하여 OS 커널에 이 시스템 콜을 처리하게 한다.

## Time sharing

Time sharing은 CPU 실행 시간을 time quantum으로 나누고 타이머 인터럽트에 따라 프로세스를 교대한다. 사용자는 여러 프로그램이 동시에 동작하는 것처럼 느끼지만, 단일 CPU(물리적인 단위로서의 단일 코어)에서는 한 순간에 하나의 실행 흐름만 실제로 CPU를 사용한다. 

Multiprogramming이 여러 프로그램을 메모리에 두고 자원을 활용하는 운영 방식이라면, time sharing은 실행 시간을 나누는 방식에 초점을 둔다.

### 실행 순서의 예

다음 두 프로그램을 각각 실행한다고 하자.

```text
P1: CPU 계산 -> 디스크 읽기 대기 -> 결과 처리
P2: CPU 계산 -> CPU 계산 -> 종료
```

P1이 디스크를 기다리는 동안 운영체제가 P2를 실행하면 CPU 대기 시간이 줄어든다. P1이 다시 실행되는 시점은 P2의 계산량, I/O 완료, 타이머 인터럽트와 스케줄러 정책에 따라 달라진다. 따라서 동시성 프로그램의 출력 순서를 임의로 고정해서는 안 된다.

## 통신과 클라이언트/서버

동시성과 통신이 결합되면 네트워크 애플리케이션이 된다.

1. 서버가 요청을 받을 자원과 서비스를 준비한다.
2. 클라이언트가 서버에 요청을 보낸다.
3. 서버가 요청을 처리한다.
4. 서버가 결과를 응답한다.

서버가 여러 클라이언트 요청을 처리하려면 프로세스나 스레드, 비동기 I/O 같은 동시성 기법이 필요하다.

```text
클라이언트 A -- 요청 A --> 서버
클라이언트 B -- 요청 B --> 서버
						 |-- worker A
						 |-- worker B
```

서버가 요청마다 작업 흐름을 분리하면 한 요청의 대기가 다른 요청을 완전히 막지 않도록 설계할 수 있다. 대신 공유 로그, 캐시, 연결 목록을 여러 흐름이 수정할 때는 동기화가 필요하다.
