C 소스 파일은 바로 실행되는 것이 아니다. 전처리와 컴파일을 거쳐 오브젝트 코드가 되고, 링커가 여러 오브젝트 파일과 라이브러리를 연결해 실행 파일을 만든다.

```bash
gcc hello.c
./a.out
```

출력 파일 이름을 지정하려면 `-o` 옵션을 사용한다.

```bash
gcc hello.c -o hello
./hello
```

현재 디렉터리의 실행 파일은 셸이 자동으로 찾지 않을 수 있으므로 `./hello`처럼 경로를 명시한다. 실행 권한이 없으면 권한을 확인하고 `chmod u+x hello`를 사용한다. ~난 귀찮아서 chmod +x 쓴다.~ ~사는 것도 귀찮으니 죽는 게 맞지 않니?~<br>
참고로 u+x와 x에 대한 차이점을 1장에서 말 안한 것 같아서 톺아보자면, u+x는 현재 사용자만, x는 해당 시스템의 모든 사용자한테 권한 주는 거라 생각하면 된다. 알면서 쓰길 바란다.

## 여러 소스 파일

헤더 파일은 선언과 인터페이스를 제공하고, `.c` 파일은 구현을 제공한다. 여러 구현 파일을 하나의 실행 파일로 묶을 수 있다. 

```bash
gcc main.c hello.c -o hello
```

컴파일 오류와 링크 오류는 원인이 다르다. 선언이나 문법 문제는 컴파일 단계에서, 함수 구현이 빠졌거나 라이브러리 연결이 안 된 문제는 링크 단계에서 나타난다. C를 똑바로 들었다면 모를 수가 없다.

### 오류 종류를 구분하는 예

```c
/* main.c */
#include "message.h"

int main(void) {
	print_message();
	return 0;
}
```

헤더 파일이 없으면 `gcc main.c message.c -o app` 단계에서 컴파일 오류가 난다. 반대로 헤더에 `print_message` 선언은 있지만 `message.c`를 명령에 빠뜨리면 컴파일은 통과해도 링크 단계에서 `undefined reference` 오류가 난다. 

## 디버깅 도구

`gdb`는 프로그램을 중단점에서 멈추고 변수와 호출 스택을 확인할 때 사용한다. 시스템 프로그래밍에서는 메모리 오류, 프로세스 분기, 반환값 문제를 출력만으로 추적하기 어려우므로 디버거 사용법이 중요하다.<br>
* 운영체제에선 `errno`를 확인하고 `perror()`나 `strerror()`를 통해 구체적인 원인을 파악할 수 있고 `WIFEXITED`, `WEXITSTATUS` 같은 OS 매크로 함수를 사용하여 종료된 자식 프로세스가 전달한 정밀한 반환값을 해석할 수 있다.<br>

## Make가 필요한 이유

예제 디렉터리에는 여러 C 파일이 있고 각각을 매번 긴 `gcc` 명령으로 컴파일하면 실수가 늘어난다. `make`는 소스 파일과 헤더 파일의 변경 시점을 확인해 필요한 대상만 다시 빌드한다.

```bash
make
make clean
```

Makefile에는 보통 대상(target), 의존성(dependency), 실행 명령(recipe)이 들어간다. 소스가 바뀌면 관련 대상만 다시 만들고, 변경되지 않은 대상은 재사용하는 것이 핵심이다.

```make
CC = gcc
CFLAGS = -Wall -Wextra

app: main.o message.o
	$(CC) $(CFLAGS) main.o message.o -o app

main.o: main.c message.h
message.o: message.c message.h

clean:
	rm -f app main.o message.o
```
 ~나도 이거 어떻게 쓰는지 모른다~

Makefile의 명령 앞에는 공백이 아니라 탭이 필요하다. `main.c`나 `message.h`가 바뀌면 관련 오브젝트 파일부터 다시 만들고, 변경되지 않은 오브젝트는 재사용한다.

대략적인 사용과정은 아래와 같다.

1. `pwd`와 `ls`로 소스 위치를 확인한다.
2. 단일 파일은 `gcc source.c -o program`으로 빌드한다.
3. `./program`으로 실행하고 종료 상태를 확인한다.
4. 여러 파일은 Makefile과 `make`를 사용한다.
5. 오류가 나면 컴파일 오류인지 링크 오류인지 구분한다.
