# 06. C의 오류 처리와 Buffer Overflow

여기까지 했으면 할만큼 한 것 같다는 망상이 들겠지만, 우리는 더 많은 것을 신경써야 한다.<br> 하프 마라톤에서 10km 부근이 우리의 오만함을 불러일으키듯이<br>
여기서 주저앉으면 신기한 점수를 받을 것이다. ~내가 해봐서 안다~<br>

프로그램은 정상적인 입력만 받는다는 보장이 없다.<br>
그리고 시스템 콜은 언제든 실패할 수 있다.<br>
그런데 C는 프로그래머가 반환값을 무시해도 뭐라고 하지 않는다. ~너이게이C~ <br>
그래서 C에서는 실행과 올바르게 처리됐다는 것이 동일한 의미를 가지고 있지 않다. 

## 오류 경로까지 프로그램의 일부 ~오류는 문화다 오류조이고~

C 함수와 UNIX 시스템 콜은 실패할 수 있지만, C 언어는 반환값을 자동으로 검사하도록 강제하지 않는다. 정상 경로에서만 파일과 메모리를 정리하면 오류가 난 순간 자원이 남거나 잘못된 상태가 다음 연산으로 전달된다.

```c
int fd = open("data.txt", O_RDONLY);
if (fd == -1) {
    perror("open");
    return 1;
}
```
- 이 코드는 단발성 실행에선 메인 함수가 종료될 때 커널이 파일 디스크립터를 알아서 정리하므로 문제가 드러나지 않는다.<br>
하지만 이 구문이 반복 실행되는 경우 fd가 파일 디스크립터 테이블에 계속 남고, 더 이상 파일을 열 수 없는 File Descriptor Leak 상태에 빠지게 된다.

따라서 호출 결과를 사용하기 전에 성공 여부를 확인하고, 실패하면 호출자가 이해할 수 있는 오류를 반환해야 한다.<br> 
이에 더해 시스템 콜 실패 시 `errno`를 함께 기록하면 원인 추적이 쉬워진다.

## 반환값과 `errno`

전통적인 UNIX 함수는 실패를 특별한 반환값으로 알린다.

| 반환값 | 일반적인 의미 |
|-|-|
| `-1` | 시스템 콜 실패 |
| `NULL` | 포인터를 반환하는 함수의 실패 |
| `0` | EOF, 성공적인 종료, 데이터 없음 등 함수별 의미 |
| 양수 | 처리한 바이트 수, PID, 성공 상태 등 함수별 의미 |

실패한 함수가 `errno`에 오류 번호를 남기면 `perror`나 `strerror`로 사람이 읽을 수 있는 메시지를 확인할 수 있다.

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>

if (fd == -1) {
    int saved_errno = errno;
    fprintf(stderr, "open failed: %s\n", strerror(saved_errno));
}
```

`errno`는 모든 함수 호출마다 0으로 초기화되는 전역 변수처럼 사용하면 안 된다.
먼저 함수의 반환값으로 실패를 확인하고, 그 직후 원인을 읽어야 한다.

## 버퍼와 문자열 종료 문자

버퍼는 데이터를 저장하기 위해 확보한 메모리 공간이다. C 문자열은 문자들의 끝을 `\0`이라는 종료 문자로 표시한다. 따라서 80바이트 배열에는 최대 79개의 입력 문자를 안전하게 저장할 수 있다.

```c
char buf[80];
scanf("%79s", buf);
```

다음과 같이 길이 제한 없이 `%s`를 사용하면 입력이 버퍼 크기를 초과할 수 있다.

```c
scanf("%s", buf);      /* 입력 길이 제한이 없음 */
```

공백을 포함하는 한 줄을 읽을 때는 `fgets`를 사용할 수 있다.

```c
char buf[80];
if (fgets(buf, sizeof buf, stdin) == NULL) {
    if (feof(stdin)) {
        /* 입력 종료 */
    } else {
        perror("fgets");
    }
}
```

`fgets`는 최대 `sizeof buf - 1`개의 문자를 읽고 종료 문자를 위한 공간을 남긴다. 개행도 버퍼에 들어올 수 있으므로 문자열 비교 전 필요하면 개행을 제거한다.

## Buffer Overflow란?

함수가 호출되면 스택에 활성화 레코드가 만들어지고 지역 변수, 매개변수, 반환 주소 등이 배치된다. 버퍼를 초과한 입력은 인접한 지역 변수나 저장된 실행 정보를 덮어쓸 수 있다.

Buffer Overflow는 입력 데이터가 버퍼의 크기를 넘어 인접한 메모리까지 덮어쓰는 현상이다. 배열을 벗어난 순간 반드시 즉시 오류가 발생하는 것은 아니다. 운이 나쁘면 별 문제 없이 실행되기 때문에 발견이 늦어진다.

```text
낮은 주소                         높은 주소
| password[10] | x | saved frame pointer | return address |
                     ^
                     버퍼 밖 입력이 이 영역까지 덮을 수 있음
```

함수 호출 중에는 스택에 활성화 레코드가 만들어진다. 지역 변수, 매개변수, 반환 주소 등이 이 레코드에 배치될 수 있기 때문에 버퍼 바깥으로 쓰는 행위가 단순히 빈 공간에 쓰는 것으로 끝나지 않을 수 있다.

### 비밀번호 검사 실험

전사에서 설명한 `checkpasstest` 유형의 예제는 Buffer Overflow가 프로그램의 판단을 어떻게 바꿀 수 있는지 보여준다.

1. 함수가 작은 문자 배열과 인증 결과 변수 `x`를 스택에 만든다.
2. 사용자에게 비밀번호 문자열을 입력받는다.
3. 짧고 올바른 입력에서는 비교 결과에 따라 `x`가 1 또는 0이 된다.
4. 배열 크기보다 긴 입력에서는 뒤쪽 메모리까지 덮어써 `x`의 값이 바뀔 수 있다.
5. 그 결과 틀린 비밀번호도 성공으로 처리되거나 프로그램이 충돌할 수 있다.

실행할 때마다 정확히 같은 변수 위치나 입력 길이가 보장되는 것은 아니다. 컴파일러, 최적화, 운영체제의 메모리 보호 기능에 따라 결과가 달라지므로 특정 길이를 외우는 것보다 **경계 검사가 없으면 데이터와 제어 정보가 함께 손상될 수 있다**는 원리를 확인해야 한다.

## 수정할 때의 관점

입력 단계에서 길이를 제한하는 것이 가장 좋다. 이미 문자열을 받은 뒤 복사해야 한다면 목적지 크기와 종료 문자를 함께 고려해야 한다.

```c
int check_password(const char *input) {
    char password[8];
    size_t length = strlen(input);

    if (length >= sizeof password) {
        return 0;
    }
    memcpy(password, input, length + 1);
    return strcmp(password, "mypass") == 0;
}
```

## 결과와 보안 영향

오버플로의 결과는 메모리 배치와 입력에 따라 달라진다.

- 눈에 띄는 문제가 없이 실행될 수 있다.
- 다른 변수의 값이 바뀔 수 있다.
- 잘못된 주소를 실행해 충돌하거나 core dump가 생길 수 있다.
- 반환 주소나 권한 관련 상태가 변조될 수 있다.

예를 들어 입력 배열과 인증 결과 변수가 다음 순서로 놓였다고 가정하면, 제한 없는 복사가 결과 변수까지 덮을 수 있다.

```c
int check_password(const char *input) {
    char password[8];
    int accepted = 0;

    strcpy(password, input);  /* password 크기 검사가 없음 */
    if (strcmp(password, "mypass") == 0) {
        accepted = 1;
    }
    return accepted;
}
```

이 코드는 입력이 짧을 때만 우연히 정상 동작하며, `strcpy`가 `password`의 경계를 확인하지 않는 것이 근본적인 문제다. `accepted`를 직접 조작하는 입력을 만들 수 있는지는 컴파일러와 스택 배치에 따라 달라지지만, 프로그램이 그런 결과에 의존해서는 안 된다.

1988년 Morris 웜 사례처럼 네트워크 서비스의 버퍼 오버플로는 시스템 전체에 영향을 줄 수 있다. 특히 root 권한으로 실행되는 취약한 프로그램은 권한 상승의 통로가 된다.

## 방어 원칙

- 입력 최대 길이를 버퍼 크기와 종료 문자까지 고려해 제한한다.
- 시스템 콜과 라이브러리 반환값을 검사한다.
- 입력 배열과 포인터가 실제로 유효한 저장 공간을 가리키는지 확인한다.
- 오류 경로에서도 파일, 메모리, 잠금 같은 자원을 정리한다.
- 권한이 낮은 프로세스로 서비스를 실행하고 불필요한 권한을 부여하지 않는다.

## 학습 점검

- `char buf[80]`의 안전한 문자열 입력 한계는 79문자다.
- 배열 경계를 넘은 쓰기는 즉시 실패하지 않을 수 있어 더 위험하다.
- 오류 처리는 정상 동작의 부가 기능이 아니라 자원과 제어 흐름을 보장하는 코드다.
