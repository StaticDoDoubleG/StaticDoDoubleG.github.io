# Classical AI: Search, Planning, and Reasoning

## 1. AI as Problem Solving

고전적 관점에서 AI는 복잡한 문제에서 해를 찾는 문제 해결 시스템이다. 계획(Planning)은 목표에 도달하기 위한 행동의 순서를 찾는 일이며, 탐색(Search)은 가능한 상태들을 살펴 목표 상태에 도달하는 경로를 찾는 절차다.

문제를 탐색 문제로 바꾸려면 다음을 정의한다.

- **State**: 현재 세계의 스냅샷. 미로에서 현재 위치, 퍼즐의 현재 배열 등이 해당한다.
- **Action**: 한 상태를 다른 상태로 바꾸는 가능한 행동.
- **Goal**: 도달해야 하는 조건을 만족하는 상태.
- **Path cost**: 시작 상태에서 현재 상태까지 행동에 들어간 누적 비용.

예를 들어 미로에서는 칸의 위치가 상태이고, 상하좌우 이동이 행동이며, 출구 도달이 목표다. 같은 문제라도 상태를 어떻게 정의하느냐에 따라 탐색 공간의 크기와 해의 의미가 달라진다.

## 2. State Spaces and Search Costs

상태 공간은 상태와 상태 사이의 전이를 모은 구조다. **Search tree**는 시작점에서 가능한 상태를 필요할 때 동적으로 펼치는 구조이고, **state-space graph**는 같은 상태를 다시 방문하지 않도록 방문 정보를 관리한다. 그래프 관리는 순환 구조에서 무한히 같은 상태를 도는 일을 막는다.

탐색 비용을 설명하는 기호는 다음과 같다.

- $b$: 한 노드에서 나오는 평균 분기 수(branching factor)
- $d$: 가장 얕은 해의 깊이
- $m$: 탐색 트리의 최대 깊이

분기 수가 조금만 커져도 깊이에 따라 후보가 기하급수적으로 늘어난다. 따라서 알고리즘은 시간, 메모리, 해의 최적성 사이의 절충을 갖는다.

## 3. Uninformed Search

### BFS

Breadth-First Search는 FIFO 큐를 사용해 얕은 레벨부터 확장한다. 모든 간선 비용이 같다면 먼저 발견한 해가 최단 경로다.

- 완전성: 유한한 분기에서 해가 있으면 찾는다.
- 최적성: 모든 step cost가 같을 때 보장한다.
- 시간: $O(b^d)$
- 공간: $O(b^d)$

예를 들어 깊이 1보다 깊이 2의 해가 존재해도 깊이 1의 모든 후보를 먼저 확인한다. 대신 다음 레벨의 모든 프런티어를 보관해야 하므로 메모리 부담이 크다.

### DFS

Depth-First Search는 LIFO 스택으로 한 가지 가지를 끝까지 내려간 다음 막히면 되돌아온다.

- 메모리는 작다: 대략 $O(bm)$
- 시간은 최악의 경우 $O(b^m)$
- 무한한 가지가 있으면 완전하지 않다.
- 먼저 찾은 해가 최단 경로라는 보장이 없다.

### Variants

- **Depth-Limited Search**: DFS에 깊이 제한을 둔다. 무한 루프는 막지만 제한이 실제 해보다 작으면 해를 놓친다.
- **Iterative Deepening DFS**: 제한을 0, 1, 2, ...로 늘려가며 DFS를 반복한다. BFS의 완전성과 DFS에 가까운 공간 사용량을 얻는 대신 앞선 레벨을 다시 확장한다.
- **Uniform-Cost Search**: 누적 비용 $g(n)$이 가장 작은 노드를 먼저 확장한다. 비용이 음수가 아니면 최적해를 찾을 수 있다.

## 4. Heuristic Search

휴리스틱 $h(n)$은 현재 노드에서 목표까지 남은 비용을 추정한다. 문제에 대한 지식이 있으면 모든 후보를 똑같이 보지 않고 유망한 방향을 먼저 볼 수 있다.

- **Admissible**: $h(n)$이 실제 남은 비용보다 크지 않다.
- **Consistent**: 인접 노드 $n'$과 간선 비용 $c(n,n')$에 대해
  $$h(n) \le c(n,n') + h(n')$$
  를 만족한다.

### Greedy Best-First Search

$h(n)$만 가장 작은 노드를 선택한다. 목표에 가까워 보이는 방향을 빠르게 시도하지만, 이미 지불한 비용 $g(n)$을 무시하므로 돌아가는 긴 경로를 선택할 수 있다.

### A* Search

A*는 다음 평가 함수를 사용한다.

$$f(n)=g(n)+h(n)$$

여기서 $g(n)$은 실제 누적 비용, $h(n)$은 남은 비용의 추정치다. $h$가 admissible하면 최적해를 보장할 수 있다. $h(n)=0$이면 A*는 UCS와 같고, $g(n)$을 무시하면 Greedy 탐색에 가까워진다.

## 5. Monte Carlo Tree Search

MCTS는 바둑처럼 분기 수가 너무 커서 전체 트리를 펼치기 어려운 문제에서 제한된 계산량으로 유망한 가지를 찾는다. 매 반복은 네 단계로 구성된다.

1. **Selection**: 루트에서 선택 정책으로 자식 노드를 내려간다.
2. **Expansion**: 아직 펼치지 않은 자식 노드를 추가한다.
3. **Simulation**: 선택한 노드에서 종료까지 rollout한다.
4. **Backpropagation**: 결과를 경로의 노드에 되돌려 방문 수와 보상을 갱신한다.

UCB는 탐색과 활용을 조절한다.

$$UCB_j=\bar X_j+C\sqrt{\frac{\ln n}{n_j}}$$

평균 보상이 높은 노드는 활용하고, 방문 횟수가 적은 노드는 탐색한다. 반복 횟수가 $i$, 트리 깊이가 $d$, rollout 길이가 $t$라면 시간은 대략 $O(i(d+t))$, 공간은 새 노드를 저장하는 데 따라 $O(i)$로 설명할 수 있다.

## 6. Expert Systems

전문가 시스템은 특정 분야의 전문가 지식을 규칙과 사실로 저장하고 추론해 결론을 내린다.

- **Knowledge Base**: 사실, 규칙, 휴리스틱
- **Inference Engine**: 사실에 규칙을 적용해 새로운 결론 생성
- **User Interface**: 질문과 관측값을 받고 결과를 표시
- **Explanation Facility**: 어떤 규칙과 사실이 결론을 만들었는지 설명

### Inference and Uncertainty

- **Forward chaining**: 알려진 사실에서 출발해 적용 가능한 규칙을 계속 실행한다.
- **Backward chaining**: 목표 결론을 먼저 정하고 그 결론을 뒷받침하는 규칙과 사실을 찾는다.
- **Certainty factor**: 믿음의 정도를 표현한다. MYCIN이 대표적이다.
- **Probabilistic reasoning**: 확률과 베이즈 정리로 증거에 따라 믿음을 갱신한다.
- **Fuzzy logic**: `키가 크다`, `고열이다`처럼 경계가 모호한 개념을 0과 1 사이의 정도로 표현한다.

MYCIN은 감염 진단, DENDRAL은 분자 구조 추론, XCON은 컴퓨터 시스템 구성을 다룬 사례다. 그러나 전문가의 암묵지를 규칙으로 추출하는 **knowledge acquisition bottleneck**과 규칙 수 증가에 따른 유지보수 문제가 컸다. 데이터에서 표현을 학습하는 머신러닝은 이 병목을 다른 방식으로 완화하지만, 설명 가능성과 검증 가능성은 여전히 중요한 설계 과제다.

## Core Comparison

| 방법 | 지식 사용 | 장점 | 주요 위험 |
|---|---|---|---|
| BFS | 없음 | 동일 비용 최단 경로 | 메모리 폭증 |
| DFS | 없음 | 낮은 메모리 | 무한 루프, 비최적 해 |
| UCS | 경로 비용 | 비용 기준 최적성 | 비용에 따른 계산량 |
| Greedy | 휴리스틱 | 빠른 방향 선택 | 최적성 부족 |
| A* | 비용 + 휴리스틱 | 조건부 최적성 | 노드 저장 비용 |
| MCTS | 시뮬레이션 보상 | 큰 게임 트리에 적합 | rollout 품질 의존 |
